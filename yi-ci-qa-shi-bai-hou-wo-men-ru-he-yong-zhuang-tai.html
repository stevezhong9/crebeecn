一次QA失败后，我们如何用状态机提升Agent可靠性

2026-06-20 14:30辉哥8 分钟阅读3598 字

上周三凌晨两点，CreBee 的自动化视频生成 Agent 突然“发疯”。

不是报错，而是静默地执行了一个错误动作。它向三个不同的客户账号发送了包含测试语音的视频草稿。

“你好,这是自动化视频生成的测试语音”

这声音在深夜显得格外刺耳。更糟糕的是，由于缺乏前置的状态校验，这个 Agent 直接绕过了我们的内容审核队列，触发了多平台的发布接口。

那一刻，我坐在屏幕前，冷汗比代码跑得快。

普通聊天机器人答错问题，顶多只是建议偏差；但行动型 AI 一旦出错，可直接发送邮件、删除文件、触发交易，造成实打实的经济损失与数据泄露。

这次事故让我重新审视了我们引以为傲的 content ops agent 架构。我们一直沉浸在 Token 消耗的狂欢中，却忘了问自己一个最朴素的问题：你干成了多少事，而不是你烧了多少电？

Token 焦虑 vs. 结果导向

过去三年，AI 行业最重要的计量单位是 Token。

比参数、比推理、比基准测试，最后都落到同一个问题：你烧了多少 Token。Token 消耗量成为这场军备竞赛的天然标尺，烧得越多，代表下注越深。

但风向变了。

Meta 内部有一个名为 "Claudeonomics" 的排行榜，汇集了超过 8.5 万名员工的 AI 使用数据，30 天内，榜单上的总使用量突破了 60 万亿 Token，“榜一大哥”烧掉的 Token 价值高达数百万美元。

震惊之余，也引燃一场辩论：Token 消耗量，到底能不能代表一个人、一家公司“有多 AI Native”？

HubSpot 的 CEO Yamini Rangan 的回应被多次转发：outcome maxxing is greater than token maxxing。别盯着 Token 消耗狂欢了，看看你到底产出了什么结果。

黄仁勋站在算力侧把 Token 定义为工业品，提出要建 Token 工厂，比拼产能和效率。他甚至给 Token 设定了价格区间，从接近零成本，到每百万 Token 150 美元。

在黄仁勋看来，Token 不会是统一定价的标准商品，它更像电力，会出现峰谷差价、分层调度和动态定价。

阿里无招站在应用端提出“效法自然”，认为 Token 不是越多越好，而是应该像能量一样自然流动，减少无意义消耗。他的逻辑是效率，“子弹要打准，不能乱射”。

而百度李彦宏则把视角进一步拉向生态和结果交付，提出了 DAA（日活智能体数），呼吁“别数子弹了，数战果”。

投入不断增加，价值却难以衡量。 这是我们做 SaaS marketing 时最常遇到的困境。如果我们的工具只是在帮用户更快地产生垃圾内容，那这种效率毫无意义。

状态机驱动：给 AI 装上“刹车”

回到那次事故。

为什么 Agent 会直接发送测试内容？因为我们在设计工作流时，过于关注“生成速度”，而忽略了“状态校验”。

在 Agentic 系统中，实体的“状态（Status）”属性极其重要。Agent 不应盲目行动，而是监听实体状态的改变。

例如：当 [内容成品] 状态变为“素材已齐备”，且 is_test_mode == false 时，才触发 [视频剪辑 Agent] 开始工作，并最终由人工或双重确认机制触发发布。

这就是 状态机驱动（State-Machine Driven） 的核心逻辑。

传统软件的责任核心，是判断工具本身是否存在技术缺陷；那么行动式 AI 的核心责任命题，则是行动链条的设计与授权是否清晰、可追溯、可追责。

如果说传统软件的责任核心，是判断工具本身是否存在技术缺陷；那么行动式 AI 的核心责任命题，则是行动链条的设计与授权是否清晰、可追溯、可追责。

在这场龙虾热潮中，整个 AI 行业敲响了警钟：AI 商业化的核心竞争力，绝不能停留在“能否替人干活、替代人力”的浅层噱头，而在于能否建立一套权责清晰、可防可控、可追溯可追责的执行权体系。

对于 CreBee 这样的新媒体矩阵运营工具来说，我们提供的不仅是分发，更是安全边界。

从 DAU 到 DAA：新生产力的度量衡

百度提出 DAA（日活智能体数），从消耗转向结果交付。这是一个极具战略意义的信号。

DAU 之所以能成为移动时代的标准，并不是靠谁“定义”了它，而是苹果和谷歌通过 iOS 与安卓，撑起了开放的应用生态。

DAA 的故事要讲圆满，它需要的也不只是模型能力，还有真实运行的 Agent 生态。

很长一段时间，搜索都是百度的核心的产品以及重要的营收来源。搜索的底层逻辑，本质上是一种高度中心化的产品思维：抓取内容、建立索引、掌握流量分发，它强调的是“聚合”。

可 Agent 生态需要的是开放。

Create 大会上，李彦宏强调“人与智能体混合编队”“更多授权、更少管控”“更少层级、更快协同”，都是在朝着容纳大量 Agent 协作的开放生态努力。

平台上有多少 Agent 在真实运行？多少是有效交付？有多少企业客户愿意把合同审核、客服、供应链等核心流程放进百度的 Agent 体系？

这些问题的答案，才能体现出 DAA 真正的含金量。

不过它依然不是终局。

一个启动后卡住的 Agent，算 DAA；一个循环调用自己的 Agent，也算 DAA；一份没有渗入真实工作流的 AI 报告，同样可能被统计进 DAA。

所以严格来说，DAA 衡量的是“劳动投入”，而非最终的“价值交付”。

复盘：如何构建可信的 AI 原生工作流

这次 QA 失败，对我们是一次深刻的洗礼。它迫使我们重新思考 Vibe Coding 背后的工程严谨性。

在 CreBee，我们正在重构我们的 content ops agent 验证流程：

  1. 状态前置校验：任何操作触发前，必须检查当前实体的完整状态链。禁止在未明确标记为“测试环境”的情况下执行写操作。
  2. 最小权限原则：Agent 的执行权限应与任务粒度严格匹配。视频生成 Agent 无权直接调用发布接口，必须经过“内容审核”这一中间态的人工或二次 AI 确认。
  3. 可追溯日志：每一个 Action 都必须绑定唯一的 Trace ID，确保在出现问题时，能迅速定位是哪个环节的状态判断失误。

技术突破只是产业发展的基础，而安全防护、责任界定、制度规范与成熟商业闭环，才真正决定 AI 智能体能否真正走进产业、落地生根，实现长期可持续的健康发展。

作为创始人，我深知从顶尖公司起步的创业故事往往充满传奇，但真实的日常是由无数个细节堆砌而成的。

我们不需要成为下一个 Meta，也不需要立刻追赶百度的 DAA 概念。我们需要做的，是让每一个接入 CreBee 的用户，都能放心地把他们的内容资产交给我们的 Agent。

别数子弹了，数战果。

这句话不仅适用于宏观的产业叙事，也适用于我们每一次的代码提交、每一次的流程优化。

在这个 AI Native 的时代，增长不再仅仅来自流量的获取，更来自信任的积累。
